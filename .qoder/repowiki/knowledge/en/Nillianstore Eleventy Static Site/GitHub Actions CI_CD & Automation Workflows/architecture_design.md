Three independent GitHub Actions workflow files under `.github/workflows/`:
- `build-check.yml`: triggered on push to `main` and all pull requests; runs Node 18, installs deps, and executes `npx @11ty/eleventy` as a fast sanity check.
- `blog_bot.yml`: cron-scheduled weekly (Sunday midnight UTC) plus manual dispatch; sets `contents: write`, checks out with full history (`fetch-depth: 0`, `persist-credentials: true`), bootstraps Python 3.11 + `python-frontmatter`/`requests`, calls `python blog_bot.py` (uses `${{ secrets.GROQ_API_KEY }}`), then validates the generated Eleventy build and commits/pushes new `posts/*.md` and `blog_log.json` under the `nillianstore-bot` identity.
- `social_bot.yml`: cron every 8 hours plus manual dispatch; splits into two jobs — `validate-site` builds the site and sleeps 30s for Netlify deployment, then `post` depends on it, re-checks out with credentials, verifies required secrets (`GROQ_API_KEY`, `META_ACCESS_TOKEN`, `FB_PAGE_ID`, `IG_USER_ID`, `GITHUB_TOKEN`) and image accessibility, and finally runs `python social_bot.py`.
All workflows use `actions/checkout@v4` and `actions/setup-node@v4` / `actions/setup-python@v5`; secrets are injected per-step via `env:` blocks rather than job-level env, keeping each step self-contained.
